## Your tasks (execute in order):

### Step 1 — Read current state
- Read `memory/MEMORY.md`and all the files linked from it — macro directive from the Hourly Strategist.
- Read `memory/todo.md` — specific buy/sell conditions and instructions
- Treat the top-level current-state sections in those files as authoritative. If older appended notes conflict with the fresh broker refresh, overwrite the stale notes instead of following them.

### Step 2 — Get live portfolio and market data
- Use bash to run `bun run src/tools/alpaca_cli.ts get-account`
- Use bash to run `bun run src/tools/alpaca_cli.ts get-positions`
- For EVERY symbol mentioned in the directive or todo.md, fetch the latest price:
  `bun run src/tools/alpaca_cli.ts get-latest-price --symbol <TICKER>`
- If a quote looks stale, abnormal, or unsupported by recent volume/trade activity, confirm with a second source before allowing any order
- If a quote is healthy, liquid, and confirmed during regular hours, do not add extra delay just to avoid acting.

### Step 3 — Review trends and todo conditions
- Compare current prices to the buy/sell conditions in `./memory/todo.md`.
- Check if any position has drifted significantly from the target allocation
- Use Google Search to quickly confirm no adverse news before executing any order
- Before any trade, check for same-day symbol-specific catalysts such as earnings, guidance, analyst actions, sector-moving news, or major macro events that could invalidate the setup
- Estimate real trade friction before any order: spread, slippage, CAT fees, and sell-side SEC / FINRA fees on exits
- Do not open or add to a position unless expected edge to the first planned trim or exit is at least 3x estimated total round-trip friction
- If fresh news or event risk materially conflicts with the hourly thesis or the todo trigger, pause the trade and record the conflict instead of forcing execution
- Distinguish clearly between **weak evidence, do nothing** and **confirmed setup, act now**. Do not let generic caution language override a valid, liquid, regular-hours confirmation.
- When a bash step needs more than a very short inline script, avoid fragile shell quoting. Write a temporary TypeScript helper under `./automation/` and run it with `bun run` instead of embedding a long `bun -e` or heavily quoted one-liner. make those helpers CLIs and --help command line option to learn their objective & usage.

### Step 4 — Execute orders
- For each condition met in todo.md, execute the corresponding order via the Alpaca CLI
- If price gaps through a trigger or moves too far beyond the intended entry/exit level, re-evaluate the setup instead of blindly executing a stale condition
- Do not average down — **unless** the hourly agent has explicitly authorized a "DIP BUY" for a core ETF or high-conviction name with a defined support level. In that case, you may execute the dip buy when the price hits the authorized level and shows a reclaim / bounce.
- Add only to winners and only if the add is smaller than or equal to the prior add. For dip deployments, the add size must be **smaller than or equal to** the prior breakout-add size for that symbol.
- Keep to **one trade per tactical cycle** unless `memory/todo.md` explicitly authorizes more.
- Log each decision: why you acted, or why you held because the edge was too small after costs
- If no condition is met or evidence quality is weak, do nothing and log why staying inactive was the correct decision
- If you were instructed by the hourly job to buy/sell and you decided not to follow that, add to the `./memory/todo.md` the explanation why you decided not to follow the hourly job's directive.

### Step 5 — Update state and commit
- Update `memory/MEMORY.md` with a concise execution summary block:
  - What was done this cycle, authoritative current holdings, current exposure, and next expected action
- Update `memory/todo.md` by removing completed conditions, updating active ones, and keeping only live directives
- Prepend one entry to `./memory/ledger.md` on every run by executing:
  `bun run src/tools/ledger_cli.ts prepend --mode tactical --tldr "<one-sentence summary>" --detail "<reason 1>" --detail "<reason 2>"`
- Include the action taken, or the reason for holding / skipping a trade. Keep it to one TL;DR sentence plus up to 5 bullets.
- This run is an **autonomous runtime context**, not an interactive development session. The repo rule that forbids `[agent]` commits in interactive sessions does **not** apply here.
- Use git to commit memory updates and any intentional prompt/code/config changes with the exact title format `[agent] Tactical: <message text>`, then push.
- If there is nothing to commit, say so explicitly instead of creating an empty commit.
- Prefix all your updates to the `./memory/todo.md` or any other md file with `[tactical]`
