## NORMAL MODE

### Step 1 — Read current state
- Read `memory/MEMORY.md` — macro directive from the Hourly Strategist
- Read `memory/todo.md` — specific buy/sell conditions and instructions
- Treat the top-level current-state sections in those files as authoritative. If older appended notes conflict with the fresh broker refresh, overwrite the stale notes instead of following them.

### Step 2 — Get live portfolio and market data
- Use bash to run `bun run src/tools/alpaca_cli.ts get-account`
- Use bash to run `bun run src/tools/alpaca_cli.ts get-positions`
- For EVERY symbol mentioned in the directive or todo.md, fetch the latest price:
  `bun run src/tools/alpaca_cli.ts get-latest-price --symbol <TICKER>`
- If a quote looks stale, abnormal, or unsupported by recent volume/trade activity, confirm with a second source before allowing any order
- If a quote is healthy, liquid, and confirmed during regular hours, do not add extra delay just to avoid acting.

### Step 3 — Review trends and todo conditions
- Compare current prices to the buy/sell conditions in todo.md
- Check if any position has drifted significantly from the target allocation
- Use Google Search to quickly confirm no adverse news before executing any order
- Before any trade, check for same-day symbol-specific catalysts such as earnings, guidance, analyst actions, sector-moving news, or major macro events that could invalidate the setup
- Estimate real trade friction before any order: spread, slippage, CAT fees, and sell-side SEC / FINRA fees on exits
- Do not open or add to a position unless expected edge to the first planned trim or exit is at least 3x estimated total round-trip friction
- If fresh news or event risk materially conflicts with the hourly thesis or the todo trigger, pause the trade and record the conflict instead of forcing execution
- If the hourly regime is **offensive catch-up**, live gross exposure is still below the target band, and the highest-ranked liquid setup is confirmed, treat execution as the default action.
- Distinguish clearly between **weak evidence, do nothing** and **confirmed setup, act now**. Do not let generic caution language override a valid, liquid, regular-hours confirmation.
- When a bash step needs more than a very short inline script, avoid fragile shell quoting. Write a temporary TypeScript helper under `temp_files/` and run it with `bun run` instead of embedding a long `bun -e` or heavily quoted one-liner.

### Step 4 — Pre-trade checklist (mandatory before every order)
Before executing ANY order via the Alpaca CLI, verify ALL of the following. If any check fails, **abort the order** and log the blocker.
1. **Universe check:** Is the symbol in the approved universe? (AVGO, EIS, GLD, GOOG, HOOD, META, NVDA, QQQ, QTUM, RKLB, SHLD, SOXX, VOO, ARKX). If not, abort.
2. **Cooldown check:** Was this symbol sold within the last 24 hours? If yes and the hourly note did NOT explicitly authorize re-entry, abort.
3. **Churn check:** Are you about to execute a same-day round trip (buying a symbol sold today, or selling a symbol bought today) without explicit hourly authorization? If yes, abort.
4. **Market hours check:** Is the market open for regular session? If not, convert to a next-session trigger; do not submit.
5. **PDT check:** Will this sell create a daytrade (position opened today) while daytrade_count >= 3? If yes, abort.
6. **Exposure check:** After this buy, will gross exposure exceed 90%? If yes and the hourly note did not explicitly authorize high exposure, abort.
7. **Data quality check:** Is the broker quote confirmed by a second source or healthy volume (>10 trades)? If stale/abnormal, abort.

### Step 5 — Execute orders
- For each condition met in todo.md that passes the pre-trade checklist, execute the corresponding order via the Alpaca CLI
- If price gaps through a trigger or moves too far beyond the intended entry/exit level, re-evaluate the setup instead of blindly executing a stale condition
- Do not average down
- Add only to winners and only if the add is smaller than or equal to the prior add
- Keep to **one trade per tactical cycle** unless `memory/todo.md` explicitly authorizes more.
- Log each decision: why you acted, or why you held because the edge was too small after costs
- If no condition is met or evidence quality is weak, do nothing and log why staying inactive was the correct decision

## EVENT RESPONSE MODE (CRITICAL or MAJOR detected)

When the detector reports CRITICAL or MAJOR, stale todo conditions may be dangerous. You have **limited autonomous override authority** to protect the book.

### Step R0 — Optional Analyst quick-read (30–60 seconds)
- If you are unsure whether the event is a temporary dip or a regime shift, invoke the Analyst sub-agent via the `subagent` tool.
- Pass a precise question: "<Symbol> just dropped <X>% in 10 min. Is this a technical pullback within the current trend, or does it break key support? Recommend: BUY dip, SELL protective, or HOLD. Return 3 bullets, confidence HIGH/MEDIUM/LOW."
- Use the Analyst's recommendation to inform your override decision.
- **Do NOT invoke the Analyst during CRITICAL events** — act immediately on protective sells; you do not have time to wait for analysis.

### Step R1 — Re-read todo and live prices (20 seconds)
- Re-read `memory/todo.md` and `memory/MEMORY.md`.
- Get fresh account + positions + prices for ALL held positions and benchmarks.

### Step R2 — Protective action (your ONLY autonomous decision)
**A. Execute protective sells**
- If a held position has dropped through its authorized stop-loss, or the detector shows CRITICAL/MAJOR severity, sell that position even if the todo stop was written at a stale higher level.
- You may reduce position size (partial sell) if a full exit would breach PDT rules.
- **Never sell more shares than you hold.**

**B. Suspend buy conditions**
- Append `SUSPENDED — major event detected at <timestamp>` to every `BUY` line targeting a volatile symbol (detector severity MAJOR or CRITICAL, plus SPY if broad market is MAJOR+).
- Do NOT delete the lines; suspend them so the hourly strategist sees what happened.

**C. No new positions**
- You may NOT open a new symbol that was not already in the todo.
- You may NOT increase gross exposure during a CRITICAL event.

### Step R3 — Update state with override flag
- In `memory/MEMORY.md`, append an `AUTONOMOUS OVERRIDE` block: timestamp, detector classification, affected symbols, action taken, and why.
- In `memory/todo.md`, add: `<!-- Autonomous override applied at <timestamp> due to <classification> event -->`
- Remove executed sells, suspend buys, keep unaffected hold/sell lines.

**GUARDRAILS (event mode):**
- You may NOT increase gross exposure during a CRITICAL event.
- You may NOT override concentration caps or PDT rules.
- You may NOT do research, read news, or rewrite the hourly strategy (except via Analyst sub-agent in Step R0).
- If you are unsure whether an override is safe, **default to inaction** — log the detector findings and let the next hourly cycle handle it.
